# ศาสตร์การเขียนบทอ่านดวงให้ "ตรงจนน้ำตาไหล"

## When to use

โหลด skill นี้เมื่อ: เขียนบทอ่านดวง/PDF ดวงชะตา/นิยายดวง TH หรือ EN · แปลง payload ดวงจาก API เป็นโปรยที่คนอ่าน · user บอกว่าข้อความดวง "เหมือนหุ่นยนต์/แปลกๆ" · เขียน reading ให้ Astral app

กฎที่ได้จากการเขียน PDF ดวงจริง (M + Mai, ส.ค. 2026) — ผสม humanizer skill (34 AI-tells) + ตัวอย่างเสียงเขียนจริงของเจ้าของ vault

## กฎเหล็ก 10 ข้อ

1. **เขียนกับคนเดียว** — ใช้ "คุณ" ตลอด อย่าใช้ "ผู้ใช้/native/chart owner" เด็ดขาด
2. **เปิดด้วยภาพ ไม่ใช่ศัพท์** — "เตาหลอมที่ทนไฟ" ดีกว่า "Taurus Sun-ASC conjunction"
3. **ตัวเลขเป็นพยาน ไม่ใช่พระเอก** — orb/องศา เอาไว้ท้ายย่อหน้าหรือวงเล็บ ไม่เปิดประโยค
4. **เจาะแผลเป็นตรง ๆ แต่จบด้วยพลัง** — ทุกความเจ็บต้องต่อด้วย "และนี่แหละที่ทำให้คุณ..." (wound→gift arc)
5. **ห้ามศัพท์ระบบในโปรย** — module/endpoint/status/unavailable/verify = ห้าม; ถ้าต้องบอกว่าข้อมูลไม่ครบ ให้พูดว่า "บทของคุณยังไม่ถูกเขียน — เพราะคุณกำลังเขียนมันอยู่"
6. **ประโยคสั้น-ยาวสลับ** — ประโยคสามคำ ตามด้วยประโยคยาวที่หอบหายใจ
7. **คำถามที่คนคิดอยู่ในใจ** — "เคยสงสัยไหมว่าทำไมคุณทุ่มเทให้ใครมากกว่าที่คนอื่นทุ่มให้คุณ?" แล้วตอบด้วยดวง
8. **ห้าม reassurance kicker** — "และก็ไม่เป็นไรนะ" = ตัดทิ้ง จบด้วยความจริงที่หนักแน่น
9. **ชื่อดาว = ตัวละคร ไม่ใช่ข้อมูล** — "ดาวเสาร์ยืนอยู่หน้าประตู ถามว่าอะไรที่ควรอยู่ อะไรที่ควรปล่อย" ดีกว่า "Saturn return occurs 2027"
10. **จบด้วยกระจก ไม่ใช่คำสัญญา** — สรุปให้คนเห็นตัวเอง ไม่ใช่สัญญาอนาคตที่ลอย

## โครงหนึ่งหัวข้อ (4-6 บรรทัด TH + 3-5 บรรทัด EN)

```
[TH]
1. ภาพเปิด — เปรียบเทียบที่จับต้องได้ (1 บรรทัด)
2. ความจริงเจ็บ ๆ ที่คนอ่านรู้อยู่แล้วในใจ (1-2 บรรทัด)
3. ดวงยืนยันมันยังไง (ดาว+องศา สั้น ๆ) (1 บรรทัด)
4. ของขวัญที่ซ่อนในความเจ็บ (1-2 บรรทัด)
[EN] แปลไอเดีย ไม่ใช่แปลคำ — ย่อ 30% ภาษาตรงกว่า
```

## AI-tells ที่เคยเจอ (จาก humanizer 34 patterns — ตัวที่เจอบ่อยในงานดวง)

- "คำนวณจาก Swiss Ephemeris สำเร็จ" ในบทอ่าน = รายงานระบบ ไม่ใช่เล่าชีวิต
- สองภาษาในวงเล็บเดียว "ตุลย์(Libra)" — เลือกภาษาเดียวต่อประโยค
- EN แปลคำต่อคำจาก TH = แข็ง; ย่อไอเดียแล้วเขียนใหม่
- rule-of-three บังคับ ("ความรัก ความมั่นคง ความสุข") — ใช้เมื่อมันจริงเท่านั้น
- em-dash ต่อเนื่องเกิน — ใช้จุดหรือคอมมา
- จบย่อหน้าด้วยประโยคโปสเตอร์ ("มันทำให้คุณมีชีวิต") — ตัดหรือร้อยเป็นประโยคเต็ม

## ขั้นตอนการเขียน

1. ดึง payload จริงจาก API (grand/M หรือ grand/Mai) — อ่านทุก section ก่อนเขียน
2. เขียน TH ตามโครง 4 ข้อต่อหัวข้อ — อ่านออกเสียง ถ้าติด ๆ ขัด ๆ แสดงว่ายังหุ่น
3. EN = เขียนใหม่จากไอเดีย ไม่แปล
4. ตรวจด้วย humanizer: หา AI-tells → แก้ → ถามตัวเอง "จุดไหนยังเหมือนหุ่น" → แก้อีกรอบ
5. ถามสุดท้าย: "คนที่กำลังเจ็บอยู่จริง อ่านแล้วน้ำตาจะไหลไหม?" — ถ้าไม่ เขียนใหม่
